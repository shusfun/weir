0001 订阅按客户端输出兼容部分，并说明遗漏 已接受

背景
各客户端能表达的协议和字段不同。此前只要有一个节点无法转换成所选格式，整份订阅就返回失败，用户连能用的节点也拿不到。
决定
除 base64 外的所有格式（Clash / mihomo、sing-box、Surge、Loon、Quantumult X、Egern）都按目标逐个节点判断：能无损表达的字段补齐映射；不能表达的节点只排除它自己。排除后同步移除它在分组里的成员位置、因此变空的分组，以及依赖它的规则，不留悬空引用。订阅信息接口按目标返回被排除的节点、受影响的分组与规则及原因，订阅页据此提示，用户仍可继续导入兼容部分。兼容节点为零时返回明确错误。提示内容不含节点凭据。
放弃的方案
  • 任一节点失败则整份失败：一个节点拖垮全部，用户无从得知是哪个节点。
  • 静默丢弃不兼容节点：用户不知道订阅少了什么，违反「失败要暴露真实原因」。
影响
同一条订阅链接在不同客户端下节点数可能不同，订阅页必须说明差异。已有的静默丢弃（如 ShadowTLS、没有链接的条目）并入同一套提示。已有订阅链接与凭据保持有效。
依据
0.1.11 验收中多个格式整份失败；用户于 2026-11-13 确认采用「兼容部分可导入、页面明确提示遗漏」。

0002 Hysteria2 新建节点默认不带混淆 已接受

背景
Hysteria2 的内置方案默认带 salamander 混淆。混淆只在 QUIC 被封锁或限速的网络里才需要，而部分客户端格式无法表达它，带混淆的节点在这些客户端上只能被排除。
决定
新建 Hysteria2 节点默认不带混淆。混淆保留为高级选项，开启时在节点设置里标明哪些客户端将无法使用该节点。项目处于初期，不为旧数据保留兼容处理。各客户端是否支持混淆以其官方文档为准：能表达的补映射，确实不能表达的才按 0001 排除。
放弃的方案
  • 保留默认混淆、在订阅里排除并提示：默认配置就让一批客户端用不了，代价落在多数不需要混淆的场景上。
影响
默认节点的客户端覆盖面变大；需要抗封锁的场景由管理员手动开启混淆。
依据
用户于 2026-11-13 说明「不考虑迁移问题，现在还在初期阶段」，并确认按建议处理。

0003 不做 Hysteria2 端口跳跃，Gate 保持只读防火墙 已取代

取代
已被 0011 取代。
背景
节点上有端口跳跃设置，值会保存，但内核配置和订阅都没有使用它，等于静默无效。Hysteria2 服务端只监听一个 UDP 端口，端口跳跃需要在宿主上把一段端口范围转发到监听端口并在防火墙放行整段范围；Gate 目前只读取防火墙状态，不写任何规则。
决定
移除 Weir 自有节点的端口跳跃设置。Gate 继续只读防火墙：检测并提示需要放行的端口，由管理员自己放行。订阅源带来的外部节点不归 Weir 管理服务端，其链接里的端口跳跃参数正常输出到支持它的格式，不因此判为不可用。
放弃的方案
  • 现在实现端口跳跃：Gate 要新增改写宿主防火墙与转发规则的特权动作，还要处理多种防火墙工具、重启后持久化、删节点时清理、与面板自带防火墙管理的冲突。这是需要单独设计的功能，不属于缺陷修复。
  • 保留设置项但不生效：继续误导。
影响
Weir 自有的 Hysteria2 节点只有单端口。以后要做端口跳跃，需新增一条决定取代本条，并先确定 Gate 写防火墙的边界。
依据
用户于 2026-11-13 问「那开了防火墙的机器咋办」，讨论后确认按建议处理。

0004 不吸收外部订阅转换 已接受

背景
产品基线写明不吸收外部订阅转换（subconverter），因为要把含节点凭据的订阅交给第三方处理。代码里却存在一条外部转换路径，两者不一致。
决定
维持基线：所有订阅格式由本地 Go 输出，删除外部转换路径。删除前先核对它服务的场景是否已被本地输出覆盖；有覆盖不了的场景，先向用户说明，再决定补本地输出还是另作处理。
放弃的方案
  • 保留外部转换并改基线承认它：节点凭据会离开中心交给第三方，即使页面有提示也与安全底线的方向相反。
影响
订阅管理不再有外部转换后端的设置；本地缺少的格式需要在本地补齐。
依据
design.html「上游吸收」表；用户于 2026-11-13 确认按建议处理。

0005 撤销 VPS 即停止服务，记录可删除 已接受

背景
撤销 VPS 的设备身份后，中心拒绝它领取配置，但它托管的内核会继续按最后一份配置运行。已撤销的记录、配对中途失败留下的记录在控制台里无法删除。
决定
撤销即停止服务：Gate 得知自己被撤销后停掉托管的内核。已撤销的 VPS 和从未连上中心的 VPS 记录可以在控制台删除，删除时一并清理其节点及相关引用，并在确认窗里列出影响。
放弃的方案
  • 撤销只拒绝领取配置：管理员以为已停用，实际节点仍在对外服务，凭据也仍可用。
影响
撤销是有实际后果的操作，确认提示要写明节点会停止。Gate 与中心失联时无法得知撤销，这种情况下服务不会自动停止，页面按「未知」显示。
依据
用户于 2026-11-13 确认按建议处理。

0006 用户续期联动链接有效期 已接受

背景
链接是否有效取用户有效期与链接生效时间的交集。给用户续期只改用户的到期时间，链接的结束时间保留旧值，续期后链接仍被拒绝，需要逐条手改。
决定
用户续期时，结束时间等于用户旧到期时间的链接随之顺延到新的到期时间；单独设了更早结束时间的链接不动。交集语义不变。
放弃的方案
  • 续期后逐条手改链接：续期本意就是让用户继续用，多出的步骤没有价值。
  • 所有链接一律顺延：会覆盖管理员特意给某条链接设的更短期限。
影响
续期的结果里要说明哪些链接被顺延、哪些保持原样。
依据
用户于 2026-11-13 确认按建议处理。

0007 订阅到期统一返回 403 已接受

背景
两条订阅路径到期后的行为不同：/sub/:token 返回 403；/sub/g/:token 返回 200，并给出一个「已到期」的提示节点，客户端会用它覆盖原有配置。
决定
两条路径到期后都返回 403，不输出提示节点。到期说明放在订阅页。
放弃的方案
  • 统一为 200 加提示节点：客户端把提示节点当作有效配置替换掉原有内容，属于用占位结果冒充成功。
影响
到期后客户端更新失败、保留旧配置；用户需要打开订阅页才能看到到期原因。
依据
项目规则「不用占位结果冒充成功」；用户于 2026-11-13 确认按建议处理。

0008 订阅源异常空结果不覆盖旧缓存 已接受

背景
订阅源刷新后解析出 0 个真实节点时，被当作合法空结果覆盖缓存。上游到期或维护时常只返回提示节点，这会清空整个源的节点，并让引用它们的出口失效。
决定
刷新后真实节点为 0、而上一次有节点时，保留旧缓存，把该源标为异常并显示上游返回了什么。管理员确认上游确实已清空时，可以手动接受空结果。首次拉取就为空的源不属于这种情况。
放弃的方案
  • 空结果一律覆盖旧缓存：把上游的临时状态变成本地的数据丢失，且连带影响出口。
  • 空结果一律忽略：上游确实清空时本地永远对不上。
影响
异常期间用的是旧节点，页面要标明数据的时间和异常状态，不显示为正常。
依据
用户于 2026-11-13 确认按建议处理。

0009 备份导入先预览再写入 已接受

背景
导入备份时直接写入，结果只给出数量，不区分新增与覆盖，管理员在执行前看不到会改动什么。
决定
导入分两步：先解析并显示各类对象将新增多少、覆盖多少，管理员确认后才写入。导出页说明备份文件里包含哪些敏感内容。
放弃的方案
  • 直接写入：覆盖现有数据是难以撤回的操作，不应没有确认。
影响
导入多一步确认；预览与实际写入之间数据有变化时要重新预览。
依据
用户于 2026-11-13 确认按建议处理。

0010 链式节点的流量只走链式，UDP 能力写进订阅下发，服务端兜底 已接受

背景
落地只支持 TCP（如 HTTP 代理）时，现在由服务端用路由拒绝 UDP，订阅里不写 udp=false（design.html「UDP 按出口判断」）。客户端事先不知道节点不支持 UDP，要试过才退回 TCP，分组与自动选择也无法据此挑选。
决定
  • 配了落地的节点，所有流量只走这条链，不从入口 VPS 直接出去。
  • 沿整条链得出 UDP 能力：完整（落地是自己的 VPS、能在 TCP 里带 UDP 的协议节点、实测支持 UDP 的 SOCKS5）、仅 TCP（HTTP 代理、不支持 UDP 的 SOCKS5）、未知。自己的 VPS 之间用 UDP over TCP 传，到落地 VPS 再还原。
  • 能力写进每种订阅格式：Clash / mihomo udp、Surge 与 Quantumult X udp-relay、Loon udp、sing-box network: tcp；格式表达不了时按 0001 说明。
  • 服务端继续拒绝不能承载的 UDP，覆盖客户端尚未更新订阅、或客户端不认该字段的情况。
  • 新建节点时按所选落地的 UDP 能力推荐入站协议；落地仅 TCP 时提示 Hysteria2 / TUIC 的 UDP 优势用不上。
放弃的方案
  • UDP 从入口 VPS 直接出去：违背配置链式的目的，出口 IP 不一致。
  • 只靠服务端拒绝、订阅不写：客户端要试过才知道，分组选不对。
影响
design.html「UDP 按出口判断」一段随实现改写。落地 UDP 能力变化后，客户端要等下次更新订阅才知道，期间由服务端兜底。
依据
用户于 2026-11-14 说「配置了链式这个节点就必须是链式的，不然配链式干叼，但是可以转换呀」「配了链式的看链式支持去设置vps的类型下发给客户端呀」。

0011 Gate 管理 Weir 节点端口的本机防火墙 已接受

取代
0003 中「Gate 保持只读防火墙」。端口跳跃仍未实现，要做时另起一条。
背景
管理员装了 Gate 就是为了不再登录 VPS，但节点端口仍要自己上去放行，Weir 只提示「未放行」。Gate 的辅助程序本来以 root 运行。
决定
  • 建节点、改端口时，Gate 在应用配置的同时放行该节点需要的端口与协议；删节点、换端口时撤掉旧规则。已有但未放行的节点，在状态旁给「放行」动作。
  • 只经白名单动作执行，只处理 ufw、firewalld、iptables，规则持久化，并带 weir 标记，只增删带标记的规则，不碰其他规则。
  • 防火墙读不懂（如 INPUT 跳到自定义链）时不写，写明原因。
  • 结果写入节点状态与审计。云厂商安全组 Gate 改不了：本机已放行而外部实测连不上时，明确提示去安全组放行哪些端口。
放弃的方案
  • 继续只读、由管理员登录放行：与装 Gate 的目的相反。
  • 开放任意命令：违反「Agent 只执行白名单动作，不提供任意 Shell」。
影响
Gate 新增写防火墙的白名单动作，要处理三种工具、重启后持久化和删除清理。宝塔等面板的防火墙底层多为 ufw / firewalld，规则在面板里可见。接入云厂商 API 管安全组另行决定。
依据
用户于 2026-11-14 说「我既然做了gate，还给了密码，就是代表我不想去登vps呀」。

0012 测试分两段，「你 → VPS」由用户浏览器实测 已取代

取代
已被 0026 取代。
背景
现在的实测都在中心或 Gate 上做，「国内延迟」一类从管理员所在网络出发的指标只能显示未知，也分不清问题出在哪一段。
决定
  • 浏览器测「你 → VPS」：延迟与下载（fetch 测试端点）、UDP 可达与 QUIC 是否受限（WebRTC 或 WebTransport）、订阅地址能否拉到。
  • 中心（mihomo）与 Gate 继续测协议是否可用和「VPS → 落地」。页面把两段结果放在一起，指出断在哪一段。
  • Gate 的测试端点只返回测试数据、不执行任何动作，用中心签发的短期令牌并限速，不构成公网管理接口。
放弃的方案
  • 只在服务端测：测不到管理员实际的网络。
影响
浏览器不会说代理协议，只能测到 VPS 这一段的网络。测试端点的端口、证书与令牌格式实现前另行确定。
依据
用户于 2026-11-14 说「还有各种测试，也该利用用户浏览器呀」。

0013 中心统一节点库：所有来源的节点在一处管理和分配 已接受

背景
自建 VPS 上的节点、订阅源拉来的节点和用户自建的链式分在 VPS、订阅源、代理几处，订阅源页只是把拉来的节点展示一遍，没有和「给谁用」连起来。
决定
  • 管理员的「节点」页列出中心拥有的全部节点，按来源分组：自建 VPS、某个订阅源、某个用户的链式节点。
  • 分给哪些用户在节点与用户两处都能改，结果一致。自建节点另有协议、端口、证书等设置。
  • 订阅源只管来源：添加、刷新、拉取状态和挑选节点，选用的节点进节点库。
  • 订阅组、规则模板等现有能力保留，归到「订阅」分组。
放弃的方案
  • 维持按来源分页：同一件事要在多个页面之间来回。
影响
中心要提供汇总各来源节点的接口；节点组件要能区分同名节点（协议、来源 / VPS、端口、内核、状态）。
依据
用户于 2026-11-14 说「感觉要有一个全部现在中心拥有节点进行管理给哪个用户使用连贯起来」，并在讨论分工后说「按这些改原型，决策也补上」。

0014 节点、代理、规则、订阅各管一件事；用户的链式就是多一个节点 已接受

背景

决定
  • 节点：节点归节点。用户用自己的代理建链式，得到的就是他多出来的一个节点（「入口节点 → 代理」），和分给他的节点一起列在「我的节点」。
  • 代理：代理归代理。系统代理（管理员给节点和规则用）与各用户的代理在一处管理，按归属分组；同一地址合并显示并写明挂在哪几台 VPS。保存前由 VPS 实测，凭据加密存储：用户只看到地址与用户名，管理员可切换明文 / 密文，切明文记审计。
  • 规则：只管谁走哪个代理（按节点、按 VPS、按网站），带实际流量与速率。
  • 订阅：每个人只管自己的订阅，从「我的节点」里挑。管理员看别人的订阅在用户详情里。
放弃的方案
  • 出口、分流、链式合并为一个「落地」概念（本条早先的草案）：概念仍然混在一起。
  • 订阅页里给节点选「经过代理」：链式变成订阅的附属，没法在别的订阅里复用。
  • 管理员在订阅页切换用户视角：用户的东西应在用户详情里看。
影响

依据

放弃的方案
由服务端测量冒充用户浏览器路径；以配置生成成功冒充连通；使用全流量中转层或内核源码补丁。
影响
页面分别表达浏览器到 VPS 与 VPS 到落地。证书、浏览器能力和网络条件不足时显示限制，不能据此直接断言代理协议可用或运营商限速。
flows
browser.test.configure、browser.test.create、browser.test.measure、browser.test.finish、proxy.uot.probe、proxy.uot.cleanup
依据
用户确认并要求实施的“ADR 与原型剩余工作全量收尾计划”第 4、5 节。

0027 更新发现与直接跨版本升级 已接受

日期
2026-11-16
flows
update.check、system.update
背景
发布可能被作废或删除，页面访问触发的缓存检查会延迟发现新版本。
决定
中心启动后及每 15 分钟自动检查，仅检查正式且产物完整的发布，不自动安装。设置首页、顶栏、通知和弹窗共用检查快照，失败标明过期和真实原因。按版本号选择最新有效发布，支持直接跨版本升级；中间版本缺失不阻塞升级。安装前重新核对目标，已撤下则停止。新版本承担必要的增量迁移，保留身份、节点、凭据及配置。
放弃的方案
不要求逐版安装，不自动恢复已作废的发布，不在目标失效后擅自换成另一版本安装。
影响
手动检查异步执行并去重，状态轮询不等待 GitHub；安装保持管理员确认。分页与附件状态查询要求 Gate 支持当前查询能力，不支持时明确报错。
依据
用户确认「作废了这个版本，然后会发新版本……直接支持到新版本就行」，并要求实施更新检查、首层提示与跨版本升级计划。
