中心地址与 HTTPS 已有

原则：中心必须配好 HTTPS 才能使用；安装时不问域名，由管理员第一次用域名打开控制台时自动记下，以后地址变了由管理员确认更新，已配对的 Gate 自动跟着切换。中心证书由管理员在本机反代（如 1Panel）上配置和续签，Weir 不签发中心证书。

步骤什么时候系统怎么做不做什么
① 安装执行安装命令不询问域名。中心只监听 127.0.0.1:19810；安装结束提示：在反代里把域名指向这个地址并配好证书，再用 https://域名 打开完成初始化不自动申请中心证书，不改反代配置
② HTTPS 拦截每个请求经公网或反代转发的明文 HTTP 一律拒绝：接口返回 403 https_required，页面显示「中心只接受 HTTPS 访问，请先在反代上配置证书」。只有直接来自本机回环、不带任何转发头的请求放行（SSH 隧道、本地开发、单机角色的本机 Gate）；/healthz 不受限。转发头只信任本机回环反代没有关闭开关；不把 HTTP 自动跳转到 HTTPS（跳转由反代负责）；dsh 子域名的请求不走这里，只返回统一拒绝（见 dsh 子域名隐藏）
③ 首次记录管理员登录后进入控制台，且还没有记录过地址前端读取 GET /admin/center-origin（返回已记录地址、当前访问地址、当前地址能否记录、仍连旧地址的 Gate）。当前地址是 HTTPS + 域名（不是 IP、localhost 或单段主机名）时，前端自动提交一次，提示「已记录中心地址 https://…」，写审计 center.origin.set；第一次记录不需要重新验证身份经 SSH 隧道或 IP 访问时不记录、不提示；普通用户登录不触发
④ 地址不一致已记录 A，管理员正经可记录的地址 B 访问控制台顶部常驻提示「当前访问地址 B 与记录的中心地址 A 不同；订阅地址与 Gate 安装命令仍使用 A」，两个按钮：「改为当前地址」打开确认窗，列出影响（见 ⑤ ⑥）和仍连接旧地址的 Gate，要求当前密码与二次验证码；「暂不更新」只在本浏览器对这一对地址不再提示。确认后写审计 center.origin.change（记录 A → B）服务端只接受「改成当前正在访问的地址」，不能手填任意地址；不静默覆盖；不自动把 B 改回 A
⑤ 生效范围记录或更改后立即生效用户订阅地址、订阅组分享地址、托管配置地址（如 Surge managed-config）、「添加 Gate」一行命令都使用记录地址；还没有记录时按请求推导已导入客户端的旧订阅地址无法自动改，旧域名停用后需用户重新导入；通行密钥按访问域名注册，换域名后需重新注册；dsh 子域名须与控制台同站，换到其他站点后要在设置里改
⑥ Gate 切换每次心跳Gate 心跳上报自己正在连接的地址；中心回复记录地址。两者不同且 Gate 不是经回环连接时，Gate 先用新地址完成一次设备认证（签名挑战），成功后由辅助程序（root）改写 agent.json 里的中心地址再切换；失败保持旧地址，10 分钟后再试。中心按心跳上报列出「仍连接旧地址」的 Gate不经新地址认证成功就不切换；单机角色的本机 Gate 不切换；不改设备 ID 与私钥
⑦ 停用旧域名管理员自己操作反代「仍连接旧地址」列表清空后才能停用旧域名；确认窗与提示里写明这一点旧域名已失效时，没切换过来的 Gate 无法自动恢复，只能在 VPS 上重新执行「添加 Gate」命令

中心部署在中国大陆服务器时，域名需要先完成 ICP 备案，否则服务商会拦截 80 / 443；这一点由管理员负责，Weir 只在 ② 的拦截页里提示。Gate 本身也只接受 HTTPS 中心（回环除外）。

存储

已有 两种后端可选：PostgreSQL + Redis（只用 migate schema 与 migate: 前缀，不清空共享实例），或只用 SQLite + 内置键值表（安装时默认）。数据访问统一经 ent，锁与键值收进存储层接口（internal/store）。中心测试默认跑 SQLite，设 MIGATE_CENTER_STORE=postgres 跑 PG + Redis。

中心与 Gate 同步

已有 中心为每台 Gate 编译完整期望配置（带版本），Gate 长轮询领取；校验 → 应用 → 健康检查 → 失败回滚 → 上报实际状态，端口冲突时中心重新分配。配对、升级、诊断、REALITY 实测、节点测试等少数动作单独下发。

获取与更新 已有

三个内核都以独立二进制调用，不引入它们的 Go 包，内核更新不需要 Weir 发版。中心从上游 GitHub Releases 拉取（镜像回退 + 官方摘要校验），缓存后把 Gate 需要的推送过去；Gate 不访问 GitHub。每台 Gate 可单独锁定版本。

sing-box 官方发布包不含 with_v2ray_api，而按用户统计流量依赖它：由 CI 跟随上游标签按官方参数加上该标签自动编译，中心从那里拉取。

另可用 migate kernel import 离线导入内核到中心缓存。sing-box 的 CI 编译见 .github/workflows/sing-box.yml。

按版本生成配置 已有

所有内核版本都用版本档案 YAML：支持的协议与字段、已移除的选项、兼容限制、默认值，以及生成配置要用到的内核特性（features 列表，如 Xray 的 balancer、observatory，sing-box 的 urltest；「一组」出口据此判断能否自动切换）。features 没写或为空表示一项都不支持，和协议列表「为空即不限制」的含义相反。档案按严格格式解析，未知字段直接拒绝，格式加字段时要同时更新内置档案和解析代码。档案是数据文件，可单独更新，也可由 AI 出草稿（见 06）。生成器按 Gate 实际安装的版本选档案；没有对应档案的版本不能设为默认。内置档案在 internal/kernels/profiles。

已知例子：Xray 26.3.27 移除了 allowInsecure；Xray 26.10.17 的 REALITY 需要 MLKEM，与 sing-box 1.14.3 客户端不兼容，混合客户端保留 26.3.27。

自管理与端口

已有 内核使用独立目录（/opt/migate/cores、/etc/migate/gate/cores），由本项目的辅助程序托管，不碰 x-ui。保留端口 22 / 80 / 443 / 8080 / 8443 / 19810 永不分配（443 对 REALITY 的例外见下），自动分配范围 20000–60000。

已有 Gate 在心跳中上报本机正在监听的端口（读 /proc/net/tcp、tcp6、udp、udp6，能取到就附进程名）；中心分配时避开保留、已登记和已占用端口；Gate 应用前再查一次，被占用就失败并由中心重新分配。内核统计 / API 端口走同一套分配，只监听回环地址。

已有 REALITY 节点优先用 443：Gate 上报 443 空闲、且这台 VPS 上还没有别的节点占用 443 时，新建的 REALITY 节点分配 443；443 被占用（1Panel 的 OpenResty、其他网站、x-ui 等）时照常分配 20000–60000 的随机端口，节点同样可用，只是伪装不如 443 自然。是否空闲只看 Gate 上报的实际占用，不看装没装 1Panel。不经 1Panel / OpenResty 按 SNI 分流抢 443，不改占用 443 的那个服务。其他协议仍不分配 443。内核降权运行时只保留 CAP_NET_BIND_SERVICE 一项能力，用来监听 443。

伪装与场景

每个协议内置一套最稳的组合（如 VLESS 默认 REALITY + TCP），新手不需要懂。REALITY 伪装目标由 Gate 从内置列表实测：支持 TLS 1.3 与 H2、无跳转、延迟最低者入选。属于固定逻辑，不依赖 AI。

内置 11 套方案：VLESS + REALITY（推荐）、VLESS / VMess + WS + TLS、Trojan + TLS、SS2022、Hysteria2、TUIC、ShadowTLS v3 + SS2022、WireGuard、本地 SOCKS / HTTP（internal/center/presets.go）。需要证书的方案由系统按 VPS 准备证书，见下方「证书」。

已有 选完方案可展开「高级」，改这个方案的具体字段（默认值仍由方案给出，只能改方案列出的字段）；新增 WireGuard（没有按用户的流量统计，只给不限额度的用户；原因写明，不悄悄少发：建节点向导选 WireGuard 时提示「只对不限额度的用户生效」，用户详情列出因额度没发给他的 WireGuard 节点，「我的订阅」里同样写明）、ShadowTLS v3 + Shadowsocks 2022（没有通用分享链接，只出现在 Clash / sing-box 订阅）、本地 SOCKS / HTTP 方案；第 ④ 步勾选用户并直接出链接与二维码。

链式代理

流量路径：用户 → 入口 VPS → 出口（家宽 SOCKS5 或另一台 VPS）→ 网站。系统按第 ③ 步自动生成出站与路由，基于现有「按用户凭据路由到指定出站」能力。入口到出口这一跳的凭据由系统生成，流量只在入口计一次。

订阅源里的节点作出口（链式代理第 ③ 步与分流规则的出口都可以选，见 07）：

  • 单个节点：按名称完全一致匹配。
  • 一组：按名称正则筛选，全部成员都下发给 Gate，由内核按延迟自动选、出故障自动切换（sing-box 用 urltest，Xray 用 balancer + observatory）；中心不替内核挑节点。一组最多 50 个，超过时保存报错并提示收紧条件。内核版本不支持时保存报错，不悄悄退回单个节点；各内核从哪个版本开始支持写进版本档案。
  • 订阅源刷新后成员随之更新；刷新失败或一时没有匹配时保留上一次可用的；从没解析成功过时丢弃流量，不改成直连。
  • 管理员建的链式代理和分流规则可以选任意订阅源；用户自建链式代理只能选分配给他的订阅组里出现的节点，看不到其他订阅源。
  • 保存前照常由入口 Gate 实测连接，不通就报错。

已有 分流规则出口与链式代理第 ③ 步都可选；单个节点或按条件筛选的一组。一组把全部成员（最多 50 个）下发给 VPS，由内核自动选择与切换：Xray 用 balancer + observatory，sing-box 用 urltest；内核版本档案的 features 不含这些能力时保存报错（列表为空表示不支持）。刷新后出口随之更新，失败保留上一次可用的。用户自建只能选分给他的订阅组里的节点。

证书 已有

原则：加 VPS 不需要加 DNS 解析。REALITY、SS2022 不需要证书；Hysteria2、TUIC 未选证书时自签并在订阅中固定指纹，同一台 VPS 的节点共用一张（有效期 10 年，指纹长期不变；不用 IP 证书，是因为它约 6 天就换一次，固定指纹会随之失效）；已有节点保留原证书，客户端不必重新导入。Trojan、WS + TLS 默认用这台 VPS 公网 IP 的证书（Let's Encrypt IP 证书，有效期约 6 天），连接地址与证书一致。中心只下发「为这台 VPS 准备证书」，由 Gate 按下面的顺序取得；建节点向导不再有证书一步，手动上传保留为高级选项。

顺序条件做法
1VPS 上有 1Panel（≥ v2.0.16）且已填 API 密钥Gate 只经 127.0.0.1 调用 1Panel 申请本机 IP 证书，由 1Panel 的 OpenResty 应答验证并自动续签；Gate 定期读取，证书变化后重载内核。密钥只存在 Gate 本机（1Panel 的 API 密钥不能限定权限，等同这台机器的 root），中心不保存；控制台填写时中心只转发一次，不落库、不写日志、不进审计详情。1Panel 的 API 接口白名单需包含 127.0.0.1。Gate 只调用证书接口，只新增和续签自己申请的证书，不改 1Panel 的网站配置
2没有 1Panel，Gate 上报 80 端口空闲中心运行 ACME 客户端，验证时 Gate 临时在 80 端口应答（只回应验证路径，用完即关），签好后推给 Gate，到期前自动续签。80 端口被其他服务（x-ui、nginx 等）占用时不抢占，直接走第 3 种
3以上都不可用全项目共用一个「节点证书域名」（如 edge.example.com）：设置里填一次，加一条解析指向中心；中心经本机反代完成 HTTP 验证并续签，推给用到它的 Gate。节点连接地址仍是各 VPS 的 IP，该域名只作 SNI。这是兜底方案：同一把私钥会分发到所有用到它的 Gate，其中一台泄露会影响全部；该域名指向中心，会暴露节点与中心之间的关联

续签与失败：IP 证书有效期短，剩余约三分之一时开始续签，失败按退避重试并告警；中心或 Gate 离线 2–3 天就可能过期。证书已过期或状态不明时，按观测规则显示「已过期」或「未知」，不能显示为正常，相关节点不再写进订阅。

不支持节点套 CDN（需要每台 VPS 单独解析）；确需 CDN 时手动上传 Cloudflare Origin 证书。

待核实：1Panel 能否为 IP 申请证书目前没有依据（官方文档未提及，论坛有回复称发证机构不支持），从哪个版本开始支持也未知（暂按 v2.0.16）；无论结果如何，1Panel 申请失败时都继续走第 2、3 种，不卡住建节点；1Panel 证书接口的具体路径以其 Swagger（/1panel/swagger/index.html）为准，签名按 1Panel 官方文档为请求头 1Panel-Token = md5("1panel" + API-Key + 秒级时间戳) 与 1Panel-Timestamp（两端时钟需同步）；HTTP 验证是否要求已安装 OpenResty；主流客户端对 IP 证书（无 SNI）的校验行为需实测；固定指纹在各订阅格式中的写法（目前只有分享链接写入 pinSHA256，见 internal/center/sub.go；Clash / sing-box / Surge 等格式待核对），客户端不支持时不能悄悄改成跳过校验。现状：三种方式都已实现（internal/center/node_certs.go、internal/gate/panel.go，ACME 客户端 internal/acme，支持 Let's Encrypt 的 shortlived profile）。1Panel 接口按 v2 API 实现，签名写的是 md5("1panel" + API-Key + 时间戳)，与上面待核实的写法不一致，要在真实 1Panel 上核对后改正。上游 MiGate 曾由中心用 Cloudflare DNS 验证按设备签发，代码已在 W5 删除。

做什么

让管理员不用学面板：用一句话说需求，dsh 按后端提供的能力目录拼出操作草稿，管理员在 Weir 的确认窗里看懂、改好、确认（见下方「能力目录」）。另外：伪装与场景推荐（如「移动宽带、UDP 受限、看流媒体」）；分流规则与处理链生成；读取内核更新说明后提出版本档案修改，不用等项目发版；日志解读。

怎么测

由系统执行，不让 AI 运行：中心把测试作为动作下发给目标 Gate，Gate 先用目标版本内核自检，再在自己的回环地址临时起实例、用客户端内核真连一次，能查出握手不兼容这类问题；用完即删，不影响正在运行的节点。

边界

AI 只提交草稿，自己不能执行、不能确认（唯一例外是让控制台跳页，不改数据），不碰 Gate、不直接改正在用的配置。节点密码、UUID、订阅令牌、SOCKS5 密码、私钥不发给模型；用户名、邮箱等账号信息可以出现在管理员发起的对话里，安全事件分析仍不带来源地址、账号和令牌。AI 由托管的 dsh（DeepSeek Harness）提供，只支持 DeepSeek，Key 只在 dsh 里填写；Laya（原生 /v1/systemone）只负责判断安全事件是否可疑。模型故障不影响基础功能。

dsh 托管

与内核相同：中心下载 Node.js 与 @deepseek-ai/dsh 并按官方摘要校验，可切换、回退。dsh 以独立系统用户 migate-dsh 运行，读不到中心与 Gate 的配置和密钥，只监听回环。

抽屉与确认

设置里填 dsh 子域名，控制台右侧抽屉内嵌 dsh；子域名只接受控制台签发的一次性票据，只能在 iframe 里打开，其他途径看起来就像这个域名不存在（见下方「dsh 子域名隐藏」）。dsh 经 Weir 的 MCP 工具提交草稿，确认弹窗由 Weir 自己弹出。

插件与适配

MCP 是底层；Weir 维护的 dsh 插件提供「Weir 助手」预设与控制台上下文，默认工作区与 AGENTS.md 由 Weir 写入。dsh 升级后插件不兼容时只启用基础预设，并可用创造模式适配，产物校验、试启动后作为草稿确认。

能力目录 已有

原则：能做什么由后端登记、dsh 运行时发现；参数由 dsh 自己拼；前端只有一个通用确认窗，按参数说明展示给人看。后端新增一项能力，dsh 立即可用，不需要更新插件，也不需要另写页面。

项规则
发现MCP 的工具列表由后端能力目录生成；dsh 每次会话开始时读取。只读能力、提交草稿的能力、界面导航（见「页面感知」）分开列出
登记每项能力在后端单独登记：名称、用途说明、参数说明、风险级别（普通 / 危险）、所需角色。参数说明除类型外必须带给人看的信息：中文字段名、单位（GB、天）、枚举值的显示名、引用对象的类型（如「节点」）。执行时调用与手动操作同一个处理函数，不另写一套逻辑
白名单外以下永远不进目录：登录与重新验证身份；密钥类设置（SMTP、1Panel、WebDAV、API 令牌，DeepSeek Key 本来就只在 dsh 里）；备份导出与恢复；dsh 自身设置；中心地址；管理员账户与角色变更
读取只读能力返回脱敏状态：不含节点密码、UUID、订阅令牌、SOCKS5 密码、私钥；可以含用户名、邮箱等账号信息
提交与试运行dsh 提交草稿后，后端用手动操作的同一套校验试运行：不通过，错误原样交回 dsh 继续改，不打扰管理员；通过，生成预演结果（将新建的对象、分配的端口、额度变化、生成的凭据数量）。涉及节点与链式代理的，沿用「实测通过才可确认」
多步草稿一份草稿可以有多步（如开用户 → 分节点 → 建两个链接），后面的步骤用占位引用前面新建的对象。一次确认、整体生效，任一步失败全部不生效
确认窗只有一个通用确认窗，在 Weir 顶层页面弹出，内容从 Weir 接口读取。按参数说明生成可编辑字段：显示中文名与单位，引用显示为名称（如「香港-01」而不是编号），修改类显示改前 / 改后；不出现原始 JSON。管理员可以直接改字段再确认，改过的字段做标记。危险操作用危险样式并要求当前密码与二次验证码。dsh 无法确认
时效与冲突草稿记下所依据的数据版本，1 小时未处理自动作废。确认时相关数据已被改动则拒绝，提示让 dsh 重新生成，不在旧数据上强行套用
执行与审计以点确认的管理员身份执行；审计记为「dsh 草稿 · 管理员确认」，附草稿内容与管理员改过的字段

对象类型、字段中文名、单位与脱敏规则只有这一份，「页面感知」上报表单内容时也用它。

现状：MCP 工具由能力目录生成（internal/center/capabilities.go）：只读能力各一个工具，草稿统一用 submit_draft，list_actions 列出可提交的能力；可提交 user.create、user.update、link.create、node.update、defense.block、user.delete（危险，只能是最后一步）。插件适配草稿也在同一个确认窗里显示。

原则：dsh 有自己的子域名，但只能从控制台抽屉的 iframe 里用；任何其他途径看到的结果都和「这个域名不存在」一样。

层面规则
放行条件同时满足才转给 dsh：控制台签发的一次性票据（60 秒、只能用一次、绑定管理员会话）换得网关会话；浏览器标明来自同站且只能作为 iframe 加载（WebSocket 看 Origin）；背后的管理员会话仍然有效、账号仍是启用的管理员
统一拒绝不满足时只有一种响应：404、正文为空、不带任何 Weir 特有的响应头。没有票据、票据过期或已用、地址栏直接打开、跨站嵌入、管理员已退出或降级、dsh 已停用或未运行、明文 HTTP，全部返回这同一个响应，不区分原因
分流顺序按 Host 识别出 dsh 子域名的请求，在所有其他处理之前分流：不经过 HTTPS 拦截页、来源封禁、错误页，避免这些页面暴露这台机器上跑着 Weir
dsh 未运行控制台打开抽屉前先经 Weir 接口查 dsh 状态，未运行时在抽屉里由 Weir 显示原因；dsh 子域名本身仍只返回统一拒绝
不在别处出现dsh 子域名只出现在管理员接口的返回里。控制台的 CSP frame-src 用站点通配（如 https://*.example.com），不写具体子域名；登录页、公开页、订阅、错误信息、安装提示里都不出现
DNS 与证书（管理员配置）设置页提示：子域名用随机名（如 k3f9x2.example.com），不要用 dsh.；用泛域名证书（*.example.com），不要为这个子域名单独签证书，否则名字会写进公开的证书透明日志；最好配泛解析，让它和任意不存在的子域名解析结果一样
浏览器原生报错（可选）想要连接直接断开、浏览器显示原生错误页时，在反代里把 dsh 站点的 404 改为断开连接（OpenResty：proxy_intercept_errors on; error_page 404 = @drop; 与 location @drop { return 444; }），并让反代默认站点对未配置的域名同样断开。设置页给出这段配置，Weir 不改反代

现状：dsh 子域名在 HTTPS 拦截之前分流，所有拒绝都是同一个空正文 404；控制台 CSP 的 frame-src 用站点通配；dsh 未运行时由抽屉里的 Weir 提示原因。

MiSub 伪装页吸收，做成开关默认关闭。打开后，浏览器访问订阅地址看到伪装页，剩余流量与一键导入只能登录后在「我的订阅」里看；客户端拉取订阅不受影响（见 05）已有
MiSub 处理链脚本吸收功能，不吸收运行方式上游脚本能做的过滤、改名、排序等由受限脚本语言提供；不运行任意 JS，也不从远程加载脚本（中心存着全部节点凭据）已有 受限脚本语言；与上游脚本的覆盖程度待对照
MiGate 公共代理目录（抓取公开 SOCKS / HTTP 代理并导入为出口）不吸收公开免费代理大多不稳定，部分专门用来截取流量；把它们当出口会让用户流量经过陌生人的机器—
MiGate 中英文界面不吸收个人使用，只有中文；不为每个页面和错误提示维护两份文案—
MiSub 外部订阅转换（subconverter）不吸收所有格式由本地 Go 输出；外部转换要把含节点凭据的订阅交给第三方处理—

08安全底线

规则执行 · 模型辅助

人的身份

管理员登录二次验证；后端强制校验角色与资源归属，隐藏菜单不能代替鉴权。中心只接受 HTTPS（本机回环直连除外），更改中心地址需重新验证身份（见 中心地址与 HTTPS）。

登录限速、会话撤销、恢复机制。普通用户只能看到和管理自己的链接、节点、链式代理。

设备的身份

Gate 主动连中心；配对凭证短时、一次性；每台设备独立身份，可单独撤销。

Agent 只执行允许的业务操作，拒绝重放与跨设备指令，不提供任意 Shell。

行为与数据

记录谁、何时、对哪台设备、做了什么，以及结果。管理员可看所有用户配置原文。

观测缺失显示「未知」，不能显示正常或 0。私钥、令牌、真实订阅凭据不入仓库与文档。
