角色内容状态
单机同一个 weir 程序装出中心与本机 Gate；本机 Gate 经回环地址自动配对，走同一套同步协议已有 本机 Gate 的 Agent 在中心进程里运行（weir-center，由 WEIR_LOCAL_GATE 指定设备文件）；内核仍由 root 辅助程序 weir-helper 托管
管理端中心服务 + 内嵌控制台，默认监听 127.0.0.1:19810，由本机反代提供 HTTPS；安装时不填域名，公共地址见下方「中心地址与 HTTPS」已有 单个 weir 程序，weir center / weir gate / weir dsh 区分角色
Gate只跑 Agent，主动连中心，不开放管理端口。「添加 VPS」有两种方式：SSH 一次装好——填 VPS 地址、端口、用户名与密码或私钥（可选择或拖入私钥文件：云厂商下载的 .pem、OpenSSH 私钥，RSA / EC / PKCS#8 / ed25519，带密码的填私钥密码；文件在浏览器里读出内容，不单独上传；不支持 PuTTY 的 .ppk，提示用 PuTTYgen 导出 OpenSSH 格式；超过 16 KB 拒绝），中心先只握手取主机指纹给管理员核对，核对后登录上去执行与下一种相同的安装命令，日志实时显示，装完断开，等到这台 VPS 配对并发出第一次心跳才算成功；复制安装命令——生成带一次性配对凭证（1 小时）的一行命令，自己以 root 执行。两种都自动安装、配对、上线已有 SSH 只连公网地址；登录密码与私钥只在这次任务的内存里，不存库、不写日志与审计、不给 dsh，日志里的配对凭证与密码遮盖；用户不是 root 时经 sudo（密码从标准输入给 sudo，私钥登录要免密 sudo）；安装时主机指纹与核对的不一致立即中止；中心还没记录 HTTPS 地址时不能用（VPS 不知道连哪里）。中心在国内、连不上 VPS 的 SSH 端口时如实报超时，改用复制命令
架构支持 linux amd64 与 arm64。发版同时打两个架构的包并写进 checksums.txt；在线安装脚本按 uname -m 选包。中心给 Gate 安装或升级时，同架构直接用自己的程序，不同架构从 GitHub Release 取对应包、按摘要校验并缓存后提供，Gate 仍不访问 GitHub。用户不选架构已有 arm64 只在 QEMU 容器里验收过，没有真实 arm64 机器

中心地址与 HTTPS 已有

原则：中心必须配好 HTTPS 才能使用；安装时不问域名，由管理员第一次用域名打开控制台时自动记下，以后地址变了由管理员确认更新，已配对的 Gate 自动跟着切换。中心证书由管理员在本机反代（如 1Panel）上配置和续签，Weir 不签发中心证书。

步骤什么时候系统怎么做不做什么
① 安装执行安装命令不询问域名。中心只监听 127.0.0.1:19810；安装结束提示：在反代里把域名指向这个地址并配好证书，再用 https://域名 打开完成初始化不自动申请中心证书，不改反代配置
② HTTPS 拦截每个请求经公网或反代转发的明文 HTTP 一律拒绝：接口返回 403 https_required，页面显示「中心只接受 HTTPS 访问，请先在反代上配置证书」。只有直接来自本机回环、不带任何转发头的请求放行（SSH 隧道、本地开发、单机角色的本机 Gate）；/healthz 不受限。转发头只信任本机回环反代没有关闭开关；不把 HTTP 自动跳转到 HTTPS（跳转由反代负责）；dsh 子域名的请求不走这里，只返回统一拒绝（见 dsh 子域名隐藏）
③ 首次记录管理员登录后进入控制台，且还没有记录过地址前端读取 GET /admin/center-origin（返回已记录地址、当前访问地址、当前地址能否记录、仍连旧地址的 Gate）。当前地址是 HTTPS + 域名（不是 IP、localhost 或单段主机名）时，前端自动提交一次，提示「已记录中心地址 https://…」，写审计 center.origin.set；第一次记录不需要重新验证身份经 SSH 隧道或 IP 访问时不记录、不提示；普通用户登录不触发
④ 地址不一致已记录 A，管理员正经可记录的地址 B 访问控制台顶部常驻提示「当前访问地址 B 与记录的中心地址 A 不同；订阅地址与 Gate 安装命令仍使用 A」，两个按钮：「改为当前地址」打开确认窗，列出影响（见 ⑤ ⑥）和仍连接旧地址的 Gate，要求当前密码与二次验证码；「暂不更新」只在本浏览器对这一对地址不再提示。确认后写审计 center.origin.change（记录 A → B）服务端只接受「改成当前正在访问的地址」，不能手填任意地址；不静默覆盖；不自动把 B 改回 A
⑤ 生效范围记录或更改后立即生效用户订阅地址、订阅组分享地址、托管配置地址（如 Surge managed-config）、「添加 Gate」一行命令都使用记录地址；还没有记录时按请求推导已导入客户端的旧订阅地址无法自动改，旧域名停用后需用户重新导入；通行密钥按访问域名注册，换域名后需重新注册；dsh 子域名须与控制台同站，换到其他站点后要在设置里改
⑥ Gate 切换每次心跳Gate 心跳上报自己正在连接的地址；中心回复记录地址。两者不同且 Gate 不是经回环连接时，Gate 先用新地址完成一次设备认证（签名挑战），成功后由辅助程序（root）改写 agent.json 里的中心地址再切换；失败保持旧地址，10 分钟后再试。中心按心跳上报列出「仍连接旧地址」的 Gate不经新地址认证成功就不切换；单机角色的本机 Gate 不切换；不改设备 ID 与私钥
⑦ 停用旧域名管理员自己操作反代「仍连接旧地址」列表清空后才能停用旧域名；确认窗与提示里写明这一点旧域名已失效时，没切换过来的 Gate 无法自动恢复，只能在 VPS 上重新执行「添加 Gate」命令

中心部署在中国大陆服务器时，域名需要先完成 ICP 备案，否则服务商会拦截 80 / 443；这一点由管理员负责，Weir 只在 ② 的拦截页里提示。Gate 本身也只接受 HTTPS 中心（回环除外）。

存储

已有 两种后端可选：PostgreSQL + Redis（只用 weir schema 与 weir: 前缀，不清空共享实例），或只用 SQLite + 内置键值表（安装时默认）。选 PostgreSQL + Redis 时中心先探测本机实例：认出 1Panel 装的（读 1panel/apps/<应用>/*/.env）就填好地址、账号和推荐的空库，Redis 只设了密码时 ACL 用户留空；密码只告诉页面「已读到」，密码框留空时由中心自己补上，不经过浏览器。已有 Weir 账户的库不能重新初始化，提示恢复原配置或换空库。数据访问统一经 ent，锁与键值收进存储层接口（internal/store）。中心测试默认跑 SQLite，设 WEIR_CENTER_STORE=postgres 跑 PG + Redis。

自更新 已有

「系统设置 → 版本与更新」显示当前版本、GitHub 上的最新正式版与更新说明；有新版本时管理员通知也会提示。点「更新」要当前密码与二次验证码。中心以普通用户运行、不能替换程序，只把请求（动作 + 版本号）写进 /var/lib/weir/update/request.json；root 的 weir-update.path 触发 weir self-update --apply：自己从 GitHub 取发布（镜像回退、可续传）、按官方摘要校验，用包里的安装脚本安装，启动失败自动切回上一版本。进度与日志写回 status.json，页面在服务重启后接着显示，版本变了自动刷新。root 不使用中心下载的任何文件，所以中心被攻破也只能请求安装某个正式发布的版本。

可以切回本机保留的上一版本，或重装最近 3 个更早的正式版本；改名为 weir 之前（0.1.13 以前）的版本不在列表里。只有装了中心的机器（单机 / 管理端）在面板里更新；Gate 随后从中心自更新到同一版本。开发构建显示「不支持自更新」。终端里 root 也可以运行 weir self-update --version X / --rollback。

内核驱动 YAML 已有

内核调用只做通用能力，每个内核怎么配置、面板怎么对接，由驱动 YAML 描述。每个内核按版本范围一份；新版本用 extends 继承上一版本，只写变化。驱动按严格格式解析，未知字段直接拒绝；格式加字段时同时改解析代码和内置驱动。

  • 调用：运行参数 run 与检查命令 check（如 [run, -test, -config, "{config}"]）；只能写选项名、子命令和一次 {config}，Gate 的辅助程序启动内核前再校验一遍
  • 能力：协议、传输、安全层、特性（如 Xray 的 balancer、observatory，sing-box 的 urltest），以及与其他内核版本的兼容关系（结构化字段，推荐版本时据此避开）
  • 面板对接：每个协议建节点时的字段（类型、默认值、范围、可选值、是否必填、说明）和内置「最稳定」方案；控制台表单按它生成
  • 配置生成：按节点参数生成入站、出站、路由、分组与统计接口。写法是带占位符与条件块（按协议 / 传输 / 安全层）的结构化 YAML，不用文本模板，输出一定是合法 JSON
  • 统计与日志：模板里写统计接口与日志级别；统计端口由引擎分配（变量 stats）

驱动只覆盖 Xray 与 sing-box；mihomo 只在中心检查订阅，不需要驱动。内置驱动在 internal/kernels/drivers，格式与模板写法见 .agents/skills/weir-kernel-driver。features 没写或为空表示一项都不支持，和协议列表「为空即不限制」的含义相反。

留在引擎（Go）里：进程托管、端口分配、证书文件、凭据注入（驱动只能引用引擎提供的变量）；渲染后强制检查——统计 / API 端口只监听回环、保留端口不出现、证书只用托管路径，驱动写错也绕不过；统计接口客户端；分享链接与订阅格式（与原订阅管理用同一套协议名对应）。内核支持、引擎已有能力够用的新协议只需新增驱动；需要新的统计方式或分享链接格式时才发版。

链式代理

流量路径：用户 → 入口 VPS → 出口 → 网站。链在服务端：中心把出口写进入口 VPS 的内核配置下发，客户端不需要知道有链；不做「机场节点作前置、我们的 VPS 作落地」的客户端链。系统按第 ③ 步自动生成出站与路由，基于现有「按用户凭据路由到指定出站」能力。入口到另一台 VPS 这一跳的凭据由系统生成，流量只在入口计一次。

已有 出口类型（管理员第 ③ 步的顺序；用户自建见 05）：

  • 直接出去：从入口 VPS 访问目标。
  • 订阅源里的节点：见下方。
  • 代理：SOCKS5、HTTP、HTTPS（经 TLS 连接的 HTTP 代理，按地址校验证书），可带用户名密码。可以直接粘贴商家给的文本自动拆开：host:port、host:port:用户名:密码、用户名:密码@host:port、socks5://、http(s)://，IPv6 用方括号。
  • 另一台 VPS：另一台 VPS 上能作出口的节点（VLESS / VMess / Trojan 方案）。我们自己的家宽 VPS 也这样作出口，前提是它有公网入口；没有公网 IP 的家宽机器在上面跑一个 SOCKS5，按「代理」填。
  • 一条分享链接：vless://、vmess://、trojan://、ss://（含 SS2022）、hysteria2://、tuic://、anytls://，传输支持 TCP、WS、gRPC、XHTTP、HTTPUpgrade。订阅地址不接受：出口只能是一个确定的节点。

不支持就报错，不悄悄降级：要求跳过证书校验、只用证书指纹代替证书校验、带出口表达不了的参数（如 ShadowTLS、Snell、WireGuard、VMess alterId 不为 0）的节点不能作出口，保存时写明原因。入口节点用的内核要能作客户端连接这个出口：协议看驱动里有没有 outbound.<协议> 模板，传输看驱动的 outbound_networks（Xray 能连 TCP / WS / gRPC / XHTTP / HTTPUpgrade；sing-box 能连 Hysteria2 / TUIC / AnyTLS，不能连 XHTTP），连不了时保存报错。分流出口作用于这台 VPS 上的全部内核，每个都要能连。

已有 保存前实测：由入口 VPS 用 sing-box 客户端按出口协议真连一次，经出口访问中心的回显地址（/api/v1/ip；没有记录中心地址时访问通用连通检查地址），拿到实际出口 IP 与延迟，记在出口上，链路页据此定位。sing-box 表达不了这个出口或入口 VPS 拿不到 sing-box 时只测端口，结果里写明「只测了端口」；另一台 VPS 的节点作出口时也只测端口（入口到它的内部凭据保存后才生成，那个节点本身建节点时已实测）。一组最多试 5 个成员，有一个通就算通过。

  • 一组：按名称正则筛选，全部成员都下发给 Gate，由内核按延迟自动选、出故障自动切换（sing-box 用 urltest，Xray 用 balancer + observatory）；中心不替内核挑节点。一组最多 50 个，超过时保存报错并提示收紧条件。内核版本不支持时保存报错，不悄悄退回单个节点；各内核从哪个版本开始支持写进驱动的「能力」（见 03）。

  • 能作出口的协议与单条分享链接相同；匹配到但不能作出口的节点（协议或参数不支持、入口内核连不了、用户自建时不是公网地址）跳过并写明原因，全部跳过时保存报错。

证书 已有

原则：加 VPS 不需要加 DNS 解析。REALITY、SS2022 不需要证书；Hysteria2、TUIC 未选证书时自签并在订阅中固定指纹，同一台 VPS 的节点共用一张（有效期 10 年，指纹长期不变；不用 IP 证书，是因为它约 6 天就换一次，固定指纹会随之失效）；已有节点保留原证书，客户端不必重新导入。Trojan、WS + TLS 默认用这台 VPS 公网 IP 的证书（Let's Encrypt IP 证书，有效期约 6 天），连接地址与证书一致。中心只下发「为这台 VPS 准备证书」，由 Gate 按下面的顺序取得；建节点向导不再有证书一步，手动上传保留为高级选项。

顺序条件做法
1VPS 上有 1Panel（≥ v2.0.16）且已填 API 密钥Gate 只经 127.0.0.1 调用 1Panel 申请本机 IP 证书，由 1Panel 的 OpenResty 应答验证并自动续签；Gate 定期读取，证书变化后重载内核。密钥只存在 Gate 本机（1Panel 的 API 密钥不能限定权限，等同这台机器的 root），中心不保存；控制台填写时中心只转发一次，不落库、不写日志、不进审计详情。1Panel 的 API 接口白名单需包含 127.0.0.1。Gate 只调用证书接口，只新增和续签自己申请的证书，不改 1Panel 的网站配置
2没有 1Panel，Gate 上报 80 端口空闲中心运行 ACME 客户端，验证时 Gate 临时在 80 端口应答（只回应验证路径，用完即关），签好后推给 Gate，到期前自动续签。80 端口被其他服务（x-ui、nginx 等）占用时不抢占，直接走第 3 种
3以上都不可用全项目共用一个「节点证书域名」（如 edge.example.com）：设置里填一次，加一条解析指向中心；中心经本机反代完成 HTTP 验证并续签，推给用到它的 Gate。节点连接地址仍是各 VPS 的 IP，该域名只作 SNI。这是兜底方案：同一把私钥会分发到所有用到它的 Gate，其中一台泄露会影响全部；该域名指向中心，会暴露节点与中心之间的关联

续签与失败：IP 证书有效期短，剩余约三分之一时开始续签，失败按退避重试并告警；中心或 Gate 离线 2–3 天就可能过期。证书已过期或状态不明时，按观测规则显示「已过期」或「未知」，不能显示为正常，相关节点不再写进订阅。

不支持节点套 CDN（需要每台 VPS 单独解析）；确需 CDN 时手动上传 Cloudflare Origin 证书。

生效时间：每条链接可设开始与结束时间，都可以不填，都不填就是一直可用。实际可用时段是链接自己的时段与用户套餐到期的交集；结束时间不能晚于套餐到期，开始要早于结束。不在时段里时拉不到节点（订阅返回 403，写明未开始或已结束），VPS 也按同一时段停用这条链接的凭据（Gate 本地按时启停，中心断线也照样执行），已导入的客户端随之不能用。用户到期同理：到期后拉不到节点。

用户自建链式代理

生成一个新节点（如「香港 → 家宽」），出现在本人节点列表，任意链接可勾选，订阅按客户端格式生成。入口为管理员分给他的节点（用户不能自己建入口）；出口按顺序可选：分给他的订阅组里的节点、SOCKS5 / HTTP / HTTPS 代理（可粘贴识别）、本人有权限的另一节点、一条分享链接；不接受订阅地址。能用的协议、报错规则与实测和管理员第 ③ 步相同（见 04）。只允许公网地址，拒绝本机、内网与云元数据地址；保存前 Gate 实测连接，不通即报错，实测到的出口 IP 显示在这条链上；流量只在入口计一次；每人最多 10 条；管理员可按用户关闭。分给他的订阅组为空时，出口默认选代理。

让管理员不用学面板：用一句话说需求，dsh 按后端提供的能力目录拼出操作草稿，管理员在 Weir 的确认窗里看懂、改好、确认（见下方「能力目录」）。另外：伪装与场景推荐（如「移动宽带、UDP 受限、看流媒体」）；分流规则与处理链生成；读取内核更新说明后起草驱动，不用等项目发版（见下方「驱动草稿」）；日志解读。

怎么测

由系统执行，不让 AI 运行：中心把测试作为动作下发给目标 Gate，Gate 先用目标版本内核自检，再在自己的回环地址临时起实例、用客户端内核真连一次，能查出握手不兼容这类问题；用完即删，不影响正在运行的节点。

边界

AI 只提交草稿，自己不能执行、不能确认（唯一例外是让控制台跳页，不改数据），不碰 Gate、不直接改正在用的配置。节点密码、UUID、订阅令牌、SOCKS5 密码、私钥不发给模型；用户名、邮箱等账号信息可以出现在管理员发起的对话里，安全事件分析仍不带来源地址、账号和令牌。AI 由托管的 dsh（DeepSeek Harness）提供，只支持 DeepSeek，Key 只在 dsh 里填写；Laya（原生 /v1/systemone）只负责判断安全事件是否可疑。模型故障不影响基础功能。

08安全底线

规则执行 · 模型辅助

人的身份

管理员登录二次验证；后端强制校验角色与资源归属，隐藏菜单不能代替鉴权。中心只接受 HTTPS（本机回环直连除外），更改中心地址需重新验证身份（见 中心地址与 HTTPS）。

登录限速、会话撤销、恢复机制。普通用户只能看到和管理自己的链接、节点、链式代理；链路页只给他自己的路径与速率，管理员配置的出口只显示类型与地区（见 链路页）。

设备的身份

Gate 主动连中心；配对凭证短时、一次性；每台设备独立身份，可单独撤销。SSH 安装只在管理员核对过主机指纹后登录，只执行固定的安装命令；登录密码与私钥只用这一次，不保存、不记录、不给模型。

Agent 只执行允许的业务操作，拒绝重放与跨设备指令，不提供任意 Shell；读本机防火墙只运行固定的只读查询，不改规则；实测出口只访问中心给的 HTTPS 地址。

行为与数据

记录谁、何时、对哪台设备、做了什么，以及结果。管理员可看所有用户配置原文。

观测缺失显示「未知」，不能显示正常或 0。私钥、令牌、真实订阅凭据不入仓库与文档。
